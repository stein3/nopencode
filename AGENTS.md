## Known quirks

- Sessions created via the engine API don't appear in the TUI until refresh; cross-client live sync is not supported.
- `/workspace` inside the engine container must be the same worktree the TUI uses for session sharing.
- Stale "new session" tabs can 404 after engine restarts — delete them from the session list.

## Resource efficiency (2026-08 refactor)

- **chatserver.py is stateless (v0.2)**: every `/api` request runs its own read-only SQL against opencode.db — no full-DB RAM materialization (the old Store re-parsed all ~35k parts on every WAL mtime change; RSS grew with history). Measured 26 MB vs 156 MB steady-state. CPU re-measured under load: ~0.2%/client, <1% at 4 stress clients — a Go rewrite would buy nothing.
- **Status dots are solid circles** (no `pulse` keyframes anywhere). Kept intentionally: `.qwait` question-card text pulse, streaming-dots blink, Footer cylon — transient interaction cues, not ambient lights.
- **Pane dormancy (App.svelte)**: tabs outside active + `PANE_KEEP=5` most-recent render a placeholder (`dormant` prop → Transcript skips the msg each-block). Tab data stays in stores so remount is instant from memory; activation force-pins to bottom so no scroll restore needed. Verified: remount preserves message set, pin intact.
- **`.msg` rows use `content-visibility:auto` + `contain-intrinsic-size:auto 160px`** — offscreen rows skip style/layout/paint. Open latency (366-msg session): median 254 ms / longtasks ≤84 ms vs documented 500–700 ms / 90–156 ms before. Scroll math (maybeLoadOlder anchor, stick-to-bottom, jumpTo) unaffected.
- **Sidebar busy-poll is 10 s** (was 5 s) — halves per-client engine load; unread/busy worst-case staleness accepted.
- **Transcript endpoint windowing**: `GET /api/history/session/{id}?limit=N` returns newest-N ascending with parts fetched only for those messages (limit=50 → 207 KB/29 ms vs 3.45 MB/70 ms full on the 5.7k-part session). Client anchor jumps use capped `backfill(id, JUMP_CAP=600)` and fall back to uncapped when the anchor sits deeper; export/copy still backfill fully. Subquery gotcha: outer `ORDER BY time_created` needs the column projected inside the inner select.
- Search parity gotcha: sqlite's `lower()` is ASCII-only; `_connect()` registers a `pylower` UDF to keep unicode case-insensitivity identical to the old Python index.
- **Search results grouping (2026-08)**: `/api/search` hits carry `time` (ms epoch, from `part.time_created`) and SQL is `ORDER BY p.time_created DESC` — so the `SEARCH_CAP=300` cutoff keeps the NEWEST matches (was oldest-biased ASC). Grouping is client-side: Sidebar `groupHits()` buckets by session, sorts groups by latest-match desc, hits within group asc; header shows `relTime(latest)`. Flex gotcha: in a `space-between` header row both children shrink on overflow — `.grphead .meta` needs `flex: none` or "3m" ellipsizes to "3…". Verify: `.webtest/verify-search-groups.mjs` (local chatserver loop + headless; asserts group order vs API, hints, indent, click-through; screenshot in `.webtest/shots/search-groups.png`). Highlight (2026-08): `/api/search` snippets carry `\x00`/`\x01` sentinels around every case-insensitive match (window sliced from ORIGINAL text — casing preserved; manual scan, no regex); Sidebar `snipSegs()` parses them into `span.hl` (accent 28% tint, no `{@html}`) — raw consumers of `snippet` must strip the sentinels.
- Statics: hashed `/assets/*` served `Cache-Control: immutable`; `index.html` always revalidates via ETag/304. `.br`/`.gz` precompressed siblings are required for compression — generated by `webui/scripts/compress.mjs`, wired into `webui` `npm run build`. No siblings ⇒ silently uncompressed.
- **`webui/dist` is not in git** (ignored) — the Dockerfile is multi-stage: stage 1 runs `npm ci && npm run build` inside node:23-slim and the final image copies only `dist`. Never hand-edit dist; rebuild locally with `cd webui && npm run build` for dev, or just `docker compose build opencode-web` which builds it fresh.
- **DiffPane/monaco are lazy-loaded** (`{#await import(...)}` in App.svelte) → main bundle 313 KB vs 2,989 KB. Do not statically import monaco or DiffPane anywhere else.
- Monaco glyph icons (fold chevrons beside unchanged regions, diff arrows, widget buttons) need the codicon font; `editor.api` never imports it → icons render blank. Fix lives in DiffPane.svelte (`import 'monaco-codicons.css'`) + a vite.config.ts alias, because monaco-editor@0.56's exports map forces subpaths to `*.js` and blocks deep css imports.
- **compose.yaml**: shared defaults via `x-limits` YAML anchor (`init: true`, mem/cpus caps, json-file log rotation 10m×3). Engine overrides to 3 GB (observed 1.2 GB growth); web 256 MB. Keep `init: true` — without it PID 1 doesn't reap children and zombies accumulate.
- **Dockerfile**: no `build-essential`/pip/venv — image assumes prebuilt npm binaries and stdlib-only python3. Don't add compiling deps without restoring build tooling.
- Deploy changes: `sudo docker compose up -d --build` (image rebuild required for Dockerfile/chatserver/webui/inject edits); inject.py additionally needs the cached `/app/index.html` removed (see ttyd-web-terminal skill).

## Transcript scroll behavior (webui)

- Tab panes stay mounted under `display:none` (App.svelte), which silences their ResizeObserver (box stays 0×0) and makes the browser restore stale scrollTop on re-show — that synthetic scroll fires *after* RO delivery but *before* rAF, so pure position-based stick-to-bottom loses the pin on every tab return. Fix (Transcript.svelte): `active` prop force-snaps to bottom on activation, `onScroll` ignores events while `offsetParent` is null, and only real upward input (wheel-up / downward swipe / ArrowUp·PageUp·Home outside inputs) clears `stuck`.
- Streaming think-body pins itself in `afterUpdate()`: ResizeObserver can't work there — `max-height` caps the box size, so the observed box stops changing while content keeps growing.
- Svelte gotcha: attribute expressions like `open={p.id === someBoolean}` (string vs boolean) are silently always-false — no type error at build time (the old `lastThinkingOpen` bug that kept live thinking blocks collapsed).
- Svelte gotcha #2 (the frozen `{label()}` bug in ModelPicker): a function called in the template only re-runs when the function binding itself is dirtied — reactive vars/stores read *inside* the body are invisible to the compiler, so the collapsed model label never updated (stuck on "model…" or a raw fallback id). Fix pattern: `$: curLabel = fn($store, localVar)` and render `{curLabel}`.

## Session diff data (webui DiffPane)

- Engine `/session/{id}/diff` returns `[]` for real sessions (snapshot store has no commits) — derive per-session changes from the transcript DB instead.
- `part` table: `type`/`tool` live inside the `data` JSON — filter with `json_extract(data,'$.type')`, order by `time_created`.
- Completed `edit` parts (100% coverage) carry a real per-edit unified patch at `state.metadata.filediff.patch` (+ `metadata.diff`) — no need to synthesize old/new pairs.
- `write` parts have only new content (`input.content`; `metadata.exists`=was-overwrite). `apply_patch` has `input.patchText` in `*** Begin Patch` V4A format (Add/Update/Delete File sections), not unified.
- `type:'patch'` parts are just `{hash, files}` bookkeeping — ignore.
- Session changes endpoint (implemented): `GET /api/history/session/{id}/changes` → `{files:[{file, ops:[{k:'edit'|'write'|'patch'|'delete', t, patch?}]}]}`; edit→`filediff.patch`, write-create→`+` pseudo-patch, apply_patch→V4A split per file + converted to unified hunks (`_v4a_to_unified`, `force_add` for Add sections). Overwrites/deletes emit no patch (no before-image in transcript). JSON >1 KB is gzipped on the fly (~6x on patch-heavy sessions); ~30 ms warm.
- Client merges a file's ops via `mergePatches()` into ONE canonical multi-hunk patch — never concatenate raw patch texts (parsers stop at foreign headers).
- `applyPatchReverse()` uses tagged rows + nearest-hit continuity (seed from EOF) + longest-add-run fallback. Known-answer tests live in `/tmp/ocweb-test/`(ephemeral); regression guard shapes: real git multi-hunk patch → exact pre-image, pure-add hunk → rows deleted not blanked.
- Whole-file reconstruction drifts on huge chaotic op histories (later ops rewrite earlier additions) — inherent without snapshots; hunks view is unaffected (renders patches directly).
- DiffPane layout: monaco auto-flips side-by-side→inline below `renderSideBySideInlineBreakpoint` (900px default, opt-in flag set explicitly in DiffPane). Hunks models must swap pairs too: `parsePatch()` pads the opposite side with blank rows for side-by-side alignment — those blanks leak into inline view as stray empty lines, so inline uses `parsePatchInline()`. A ResizeObserver in DiffPane tracks the flip.

## Prompt send path (webui)

- `oc.prompt` (webui/src/lib/api.ts) uses engine `POST /session/{id}/prompt_async` — returns 204 in ms, body identical to sync `/message` (incl. `model:{providerID,modelID}`).
- UI never depended on the POST resolving: busy flag + transcript come from SSE (`session.idle`/`session.error`). api.ts `req()` now tolerates empty bodies (204).
- No async variant exists for `POST /session/{id}/command` — long-running slash commands (e.g. /compact) hold the connection until completion.
- chatserver.py proxies `/oc/*` with `timeout=600`.

## Session error tiles (webui)

- Turn failures render as **full-red tiles** (faint `rgba(244,135,113,.09)` wash + red border, not just a side chip) in three places: (1) errored **tool cards** (`.toolcard.toolerr`, `state.status==='error'` — persisted parts, always rendered); (2) **inline tiles** on the assistant message the engine stamped `$.error` on (mid-turn provider failures, persisted in opencode.db, TUI-parity — `.errtile-inline` inside the message body); (3) **sidecar end tiles** (`tab.errors` → `.msg.errtile` after the last message) for instant fails that never created a message.
- Engine facts verified: mid-turn errors are stamped on the assistant message and served by `GET /message` (`$.error = {name, data:{message,statusCode,…}}`; 98 rows in DB) — but **instant fails (bad model) create no assistant message** and the `event` table stores no `session.error` at all. Readable text sits at `error.data.message`, NOT `error.message`; fallback chain `data.message → message → name → 'error'`.
- **Aborts**: engine fires `session.error` with `MessageAbortedError` for user aborts AND stamps it on the message. TUI-parity: excluded from tiles/persistence, rendered as muted italic "session aborted" (`.aborted`). Don't "fix" this into a red tile.
- Dedupe: a mid-turn failure can exist in BOTH sources (inline $.error + sidecar row from the witnessed SSE event) — Transcript filters sidecar tiles whose text matches an inline one (`inlineErrTexts`). Errored messages with **zero renderable parts** are kept by the msgs filter (common: provider died before any part streamed).
- Sidecar persistence: sse.ts POSTs to chatserver `GET/POST/DELETE /api/history/session/{id}/errors`, backed by `webui.db` next to opencode.db (table `serr`, `UNIQUE(sid,msg)` dedupes concurrent POSTs from several clients). compose.yaml dropped the `:ro` on opencode-web's share mount for this; opencode.db itself stays mode=ro+query_only. Tiles load once per tab open (`Tab.errorsFetched` guard — also keeps the onSent refetch from re-fetching rows it has). **Tiles are history, not a banner: nothing clears them automatically** — no clear-on-send (removed 2026-08 after a followup wiped the demo tile), no clear on idle; identical repeats dedupe via UNIQUE(sid,msg). DELETE endpoint remains for manual cleanup only. Coverage limit: only errors witnessed by an OPEN webui tab get recorded (TUI-only/background instant-fails leave no tile — mid-turn ones still show via $.error).
- Cheap real trigger: `POST /session/{id}/message` with `model:{providerID:'does-not-exist',modelID:'nope'}` → 500 + SSE `session.error`. Verify scripts: `.webtest/verify-errtile-persist.mjs` (live engine; reload persistence + survives-send; mocks only `prompt_async`→502) and `.webtest/verify-errtile-render.mjs` (fully mocked payloads; inline/abort/dedupe/tool-red/zero-part). Seed rows by writing `serr` in `~/.local/share/opencode/webui.db` directly (same file the deployed chatserver uses).

## Auto-retry of retryable turn failures (webui)

- `webui/src/lib/retries.ts`: when SSE `session.error` carries `isRetryable` (engine stamps it on transient `APIError`s, e.g. upstream 503 — shape `error.data.isRetryable`), the failed turn's user message (newest user msg's text parts) is re-dispatched with backoff **1s → 2s → 3s → 5s → 15s → 30s → 60s → 2m → 5m**, then every 5m until the turn lands. Model comes from the picker (`selectedModel`), consistent with manual sends.
- Loop lifecycle: attempt count persists across dispatches per session; a dispatch that itself dies (network) counts as a failure and re-schedules. Cleared by: clean `session.idle` (only when no error since the last dispatch — engines can emit idle AFTER session.error, so clearing on idle unconditionally would kill pending retries), manual send (Composer.submit `cancelRetry`), tab close, or missing user text. Aborts (`MessageAbortedError`) are never retryable.
- UI: red countdown line under the error tiles (`.retryline` in Transcript) — "↻ retrying in 0:05 · attempt N" + cancel button; hidden while a dispatch is in flight (busy spinner covers that).
- Countdown is a 1s `setInterval` ticker → background-tab timer throttling can stretch delays; harmless (fires later, UI hidden anyway).
- Verified: `.webtest/verify-retry.mjs` + `.webtest/fake-engine.py` (fake engine on :8124 serving dist + stub /oc + scripted SSE: prompts 1–2 → retryable session.error after 1.2s, prompt 3+ → session.idle; `GET /__state` exposes recorded prompts). Covers backoff timing (6s/16s observed), attempt counting, clear-on-success, cancel button, manual-send-cancels. NOTE: fake engine must implement `POST /oc/session` (pending-tab realize) or SSE sids won't match tabs.

## Permission requests (engine API shape, verified v1.18.18)

- `GET /permission` items and the SSE `permission.asked` payload are `{id, sessionID, permission, patterns[], metadata{}, always[], tool?{messageID,callID}}` — there is NO `title`, `pattern`, `path`, or `type` field. The webui originally mapped those nonexistent fields, so pending permissions rendered as bare request-id prefixes.
- `permission` is the kind (`bash`, `edit`, `read`, `glob`, `grep`, `webfetch`, `doom_loop`, …). `metadata.input` holds the tool call input for bash (→ show `input.command`); glob/grep → `{pattern,path}`; webfetch → `{url}`; mcp reads → `{server}`. Edit asks carry the file path in `patterns[0]`.
- Human-readable detail builder lives in `webui/src/lib/permissions.ts` (`permDetail`); display in App.svelte header bar shows kind + detail with full text in `title`.
- Schema source of truth: engine `/doc` OpenAPI (`components.schemas.PermissionRequest`). Inspect a running engine's schema via `opencode serve --port <p>` + `curl /doc`; don't guess from TUI strings.

## Token/context tracking (webui)

- Engine reality: aborted turns, step-start/step-finish-only turns, and provider-silent responses permanently leave an **all-zero `tokens` object** on the newest assistant message (~28 sessions in opencode.db, 2026-08). An all-zero object is truthy, so "newest assistant message wins" logic read it as 0 context → sessions showed `—` tokens / `0% used` indefinitely.
- Fix pattern: `tokenTally()` (stores.ts) sums input+output+reasoning+cache and returns **undefined unless > 0**; `metricsFromMessages()` walks newest→oldest and OMITS the `tokens` key when nothing reported, so `patchMetrics` keeps the last good value. sse.ts guards its live `message.updated` patch with the same helper.
- Footer/InfoPanel now derive `usedTokens` from `$sessionMetrics[tab.id]` (SSE-live DURING a turn) with their busy-keyed fetch only seeding values — previously they fetched once at busy-flip = turn start, when the newest message is always a zero-tally in-flight one, and never updated until idle.
- chatserver `load_sessions()` computes a per-session context estimate via correlated subquery over `message_session_time_created_id_idx` DESC with a `TOKEN_SUM_SQL > 0` predicate — stops at first hit, ~1–2 ms for ~150 sessions. The naive window-function full scan costs ~105 ms (json_extract parses every blob) — don't use it.
- Engine session-level `tokens` on `GET /session/{id}` are CUMULATIVE all-turn totals (cache.read in the millions), NOT context size — never use them for "% used".
- Verified headless: `.webtest/verify-tokens.mjs` (sidebar 140/156 rows show tk badges; InfoPanel 93K / 9% on ses…D0hlIGZU which previously rendered `—` / 0%).

## Session status lights (webui sidebar)

- Each sidebar session row has a 7px dot with three states (source order in Sidebar.svelte matters — later rules win): `.perm` red solid (pending permission), `.busy` yellow pulsing, `.unread` accent green slow-pulse (finished while unviewed). Idle = transparent.
- Busy comes from a 5s poll of engine `/oc/session/status` in Sidebar.svelte (`busyMap`); permission from the shared `permissions` store.
- Done/unread lives in `sessionUnread` store (stores.ts). Two producers: sse.ts marks on `session.idle`/`session.error` when `tabs.getActive() !== sid` (open tabs only — SSE drops non-open sessions); Sidebar's busy-poll diffs consecutive polls to catch busy→idle for sessions with no open tab. Consumer: App.svelte `$: if ($active) clearSessionUnread($active)` clears on any tab activation (clicks, hotkeys, new chats).
- Unread state is in-memory only — lost on reload by design (no localStorage persistence).
- Subagent sessions (@explore/@general/…): engine marks them with `session.parentID` (+ `agent` name); sqlite columns are `session.parent_id`/`session.agent` (snake_case). chatserver `load_sessions()` exposes them as `parent`/`agent`; Sidebar NESTS them under their parent (chevron + count chip, indent + tree guide, per-parent collapse persisted as an EXPANDED-id set in `opencode.subExpanded` localStorage (`subExpanded` store in stores.ts — inverted so empty = all collapsed = the default; new parents collapse automatically), depth cap 2). Collapsed parents show a SOLID aggregated dot (red perm / yellow busy / dim accent unread) when a descendant needs attention — no pulse animations anywhere (resource-efficiency decision). The "hide subagents" checkbox (`hideSubagents` pref, hidden by default) still removes them from the list entirely; search hits are NOT filtered/nested. App.svelte auto-open on page load picks the most recent ROOT session only (`filter(s => !s.parent)`) — never a subagent; explicit opens (sidebar/search) still allowed. Orphan subs (parent deleted) render top-level.
- Perf (measured headless vs live engine+chatserver via vite dev): dots are NOT a meaningful click-latency factor — median click→rendered ~240–280ms for ≤60-msg sessions in all animation states; idle dots don't animate at all. Cost scales with transcript size (364 msgs ≈ 10.4k DOM nodes ≈ 500–700ms, long tasks 90–156ms from markdown/hljs render). Guards added: `will-change: opacity` on animated dots only (compositor promotion), `refreshBusy()` assigns `busyMap` only on actual change (else every 5s poll re-diffs all rows). Bench harness pattern: `.webtest/bench.mjs`.

## Windowed message loading (webui)

- Engine pagination reality (v1.18.18): `GET /session/{id}/message?limit=N` returns the NEWEST N ascending ✓; the `before` param 400s server-side in every form; the v2 `/api/session/...` tree returns empty data for legacy sessions. So paging = cumulative-limit trick (`loadOlder` fetches newest `len+OLDER_CHUNK`, applyMessages unions by id).
- Open path: `openLive` fetches RECENT_PAGE=80 → `Tab.partial` set from completeness; refetch paths (SSE debounce, Footer, InfoPanel, /undo) are limited too and pass `complete = len < limit` so `metricsFromMessages` skips overriding the sidebar's true sqlite message_count on truncated payloads.
- Scroll-up paging: Transcript `maybeLoadOlder` triggers <900px from top; anchor math keeps `scrollHeight - scrollTop` constant across prepends; auto-chaining stops at AUTO_PAGE_CAP≈400 loaded — deeper history via explicit "↑ load earlier messages" button (unbounded chaining crashed even prod headless at ~1.5k msgs/~40k nodes; desktop browsers survive but it's wasteful).
- `backfill()` (full fetch) is reserved for transcript export/copy and search-anchor jumps; App sets `Tab.jumpTo`, and TRANSCRIPT owns the scroll: reactive waits for the node, clears `stuck`, parks, clears flag — and `follow()` no-ops while `jumpTo` is pending (its force path would otherwise yank back to bottom during multi-tick row insertion; a bare rAF+scrollIntoView in App loses that race).
- CRITICAL invariant discovered: any `tabs.patch` swaps the Tab object → every consumer reactive re-fires. An async fetch whose completion patches tabs self-amplifies into a request storm (Footer once hit ~20 req/s when engine-side streaming churned tabs). Guards now: Footer keys refreshes on `${id}:${busy}` (InfoPanel already did), and `applyMessages` skips the swap entirely when fetched id-set + partial state are unchanged.
- Probe gotchas: programmatic `el.scrollTop=` fires scroll but NOT wheel events → Transcript's stuck/wheel logic never sees it; use `page.mouse.move(cx,cy)` over the pane + `mouse.wheel`. `vite preview` serves stale dist unless rebuilt after src edits.

## Model selection (engine API shape, verified v1.18.18)

- Engine exposes TWO route trees: legacy `/session/*` (what the webui uses) and a v2 `/api/session/*` tree. `POST /api/session/{id}/model` (switch session model, body `{model:{providerID,id}}`, ModelRef uses `id` NOT `modelID`) exists ONLY in the v2 tree — there is no `/session/{id}/model`. Returns 415 without `content-type: application/json`.
- `POST /session` (create) accepts `model:{providerID,id}` — sessions can be born with a model; otherwise they inherit the config default and the first turn ignores the picker.
- `POST /session/{id}/message` body accepts `model:{providerID,modelID}` (note: `modelID` here, unlike ModelRef). Explicit model wins, gets stamped on the user message AND updates session.model — even with `noReply:true`.
- `POST /session/{id}/message` while the session is busy does **not** error; the engine queues the turn and the request blocks until it completes (verified with two back-to-back prompts returning in order). This is what lets the composer show a "queue" send button while a turn is running.
- Question-tool requests: `GET /question` returns pending `{id, sessionID, questions:[{question,header,options:[{label,description}],multiple?,custom?}], tool:{messageID,callID}}`. Reply via `POST /question/{id}/reply` body `{answers: string[][]}` (one label array per question), or reject via `POST /question/{id}/reject`. SSE events: `question.asked` / `question.replied` / `question.rejected` (plus `.v2` variants). The webui stores pending questions in `pendingQuestions` and renders an interactive `QuestionPicker` inside the tool card.
- Webui default model: `preferredDefaultModel()` in `stores.ts` picks `opencode/x-preview-f-free` when available, avoiding the local lemonade runtime that is often offline in this environment.
- Webui invariant (after the "model didn't stick" bug, 2026-08): `selectedModel` store is written ONLY by user actions (topbar ModelPicker, empty-state ModelSelect). Never echo `session.model` from SSE `session.updated` or `openLive` back into it — those stream constantly during an in-flight turn carrying the OLD model and silently reverted fresh picks. Prompts always send the picker value explicitly (Composer.submit), and pending tabs realize via `createSession(title, model)`.
- Empty-state dropdown lives in `webui/src/components/ModelSelect.svelte` (native select + optgroups, mobile-friendly), rendered by Transcript.svelte only for live tabs with no messages.
- Message model-id data shapes (verified against opencode.db, 2026-08): assistant messages store FLAT `data.modelID`+`data.providerID`; **user messages store NESTED `data.model = {providerID, modelID}` and NO flat `modelID`**. Fixed 2026-08: shared helper `msgModel(info)` in `webui/src/lib/util.ts` reads both shapes (`info.modelID ?? info.model?.modelID`, same for providerID); used by `sse.ts normalizeMessages` + `stores.ts setMeta` (both fields, `new ?? existing` merge), App.svelte's pure-history fallback mapper, and typed on `OcMessage`/`HistMsg`. Transcript.svelte badge keeps bare `{m.modelID}` text but tooltip shows `provider/model`. Prompt payloads send `model:{providerID,id}` (ModelRef uses `id`); when omitted, the engine stamps its resolved default on the echoed user message. Verify script: `.webtest/verify-model-badge.mjs` (seeds 2 noReply user msgs with different models, asserts badges+tooltips, assistant parity, retroactive old-session badges; shots in `.webtest/shots/model-badge-*.png`). Known gap: chatserver.py `load_messages` (~line 241) emits only nested-derived `modelID` — no `providerID`, and assistant FLAT modelID is dropped → pure-history fallback (engine down) loses assistant badges and history tooltips degrade to bare modelID; one-line server fix if ever needed.
- ModelPicker list (2026-08): flat across providers, sorted most-recently-used first then alphabetical. Recents persist in `localStorage['opencode.modelRecents']` (cap 12) via the `recentModels` writable + `recordRecent()` in stores.ts — called only from user `pick()` handlers (same invariant as `selectedModel`; the `onMount` default-seed must NOT record recency). Svelte gotcha #3: a reactive `$: x = (() => …localStorage.getItem…)()` never re-runs when only localStorage changed — functions reading localStorage are invisible to the compiler (same family as the frozen `{label()}` bug). Keep such data in a writable store and read `$store` inside the statement. Headless check: `.webtest/verify-mru.mjs` (order, immediate re-sort on pick, persistence, provider-tag styling).

## Command palette & slash commands (webui)

- Palette commands resolve the active session at RUN time via `resolveSid()` in `CommandPalette.run()` (reads `tabs.getActive()`/`tabs.snapshot()` lazily). Regression (fixed 2026-08): App.svelte passed `sessionId={tabs.snapshot(tabs.getActive())…}` — a template expression referencing only the constant `tabs` import has ZERO reactive deps, so it evaluated once at App mount and froze at `null`; every session-scoped ctrl+p command (/rename, /copy, /export, /fork…) falsely toasted "no session yet". Composer slash cmds were unaffected (per-submit ctx).
- General rule (same family as the `{label()}` / localStorage gotchas): a Svelte template expression only re-fires on identifiers it references — store state behind method calls (`tabs.getX()`) is invisible to the compiler. Read-at-use inside event handlers sidesteps the trap entirely.
- Pending tabs (`id: pending-*`, not yet realized) must resolve to null → "no session yet" toast; verified in `.webtest/verify-palette-sid.mjs` (intercepts PATCH `/oc/session/*`, checks A→A then switch→B freshness + pending no-op).
- `/rename` opens the themed in-app `RenameDialog.svelte` (store: `renameTarget` = `{sid,title}`; App renders it beside CommandDialog) — NOT native `window.prompt()` (unstyled, blocked in some webviews). Svelte gotcha #4: seeding an input by assigning inside a `$:` block (`$: if ($renameTarget) value = $renameTarget.title`) re-runs the statement whenever the bound input invalidates `value` — user edits revert to the old title mid-dialog. Seed via a plain `renameTarget.subscribe()` callback instead (same escape hatch as commands.ts's `selModel` snapshot).

## Session fork (engine API shape, verified v1.18.18 via binary + live probe)

- `POST /session/{id}/fork` takes an UNDOCUMENTED JSON body `{messageID}` (OpenAPI /doc omits it; SDK maps it to body, handler `forkRaw` decodes). Empty/absent = whole-session copy.
- Core `Session.fork` semantics: new session is STANDALONE (no parentID → sidebar subagent badge/hide filter don't apply); copies messages strictly BEFORE the messageID (`findIndex` + `slice(0,o)` — EXCLUSIVE, TUI "Fork from message" parity); unknown messageID degrades to full copy. Message/part ids remapped, compaction `tail_start_id` remapped, metadata cloned, revert state NOT copied, source untouched. Engine emits `session.forked` SSE.
- Engine TITLES the fork itself: `"<source> (fork #N)"` — never append another "(fork)" client-side (the old /fork command double-suffixed).
- Webui: ⑂ button on user messages (Transcript.svelte `forkFrom`) → `oc.forkSession(id, mid)`; forked-from text lands in the new tab's composer via `Tab.prefill` consumed in Composer onMount (same pattern as `Tab.jumpTo`). Verify script: `.webtest/verify-fork.mjs` (seeds 3 user msgs with `noReply:true` POSTs — no LLM turns needed — clicks ⑂ on msg 2, asserts 1-row fork + composer refill + source intact, deletes probe sessions).
- `POST /session/{id}/message` with `{"noReply":true, parts:[…]}` creates a user message WITHOUT running a turn — the cheap way to seed transcript fixtures for tests.

## Webui browser verification (headless, no deploy)

- Local loop for UI tests: point chatserver at the engine: `OC_ENGINE=127.0.0.1:4096 PORT=8123 HOST=127.0.0.1 python3 /workspace/opencode/chatserver.py &`, then drive `http://127.0.0.1:8123` with the headless-browser skill (setup dir `/workspace/opencode/.webtest`, example script `verify.mjs` there).
- Gotchas: `waitUntil:'networkidle'` never fires (SSE `/oc/event` stays open) — use `domcontentloaded` + UI waits; playwright glob `**/oc/session/*/message` also matches the GET polling — filter `route.request().method() === 'POST'` and `route.fallback()` the rest; multiple tab panes stay mounted so scope composers with `#composer-input:visible`.
- Mock-route gotchas (hit 2026-08, see `.webtest/verify-queue-fix.mjs`): a route handler that returns without fulfilling/fallbacking HANGS the request — handy for simulating the engine's blocking prompt POST; route matching is last-registered-wins but order INSIDE one handler function still matters — a `^/oc/session/[^/]+$` regex silently swallows `/oc/session/status` if checked first.
- Composer send/queue semantics: `oc.prompt` POST blocks until the whole turn finishes, so `submit()` must release its `sending` flag right after dispatch (detached flight + `failedSend()` handler), else queueing (Enter + ➤) is dead for the entire turn. Late failures (proxy 600s timeout, OS sleep) must check the transcript (`failedSend`) before restoring text into the box — blind restore made backgrounded tabs "resend" the last message on return.
- Delete probe sessions afterwards: `DELETE /session/{id}` on :4096 (auto-titled `New session - <ISO>` ones created during testing).

## Grep tool outbox + match count (webui, 2026-08)

- Grep-like tool cards (`/grep|find|search/` on `p.tool`, includes gh_grep_searchGitHub) now render the same `.outbox` details as shell tools (`Transcript.svelte`), with a muted `.matchcount` footer `(n matches)` pinned under the output text. Count: parse engine's authoritative `^Found (\d+) matches` header; fallback counts `^\s+Line \d+:` rows; null → no footer (e.g. GitHub-snippet outputs).
- Verify script: `.webtest/verify-grep-count.mjs` (fixture session titled "Grep match count in opencode output"; asserts footer text equals header count + element screenshot). Sidebar rows expose only `title={s.title}` — target sessions by title, there is no deep-link/session-id URL param.
- Headless-capture gotchas hit while verifying (all solved in that script):
  - Transcript stick-to-bottom pin: programmatic `scrollIntoView` never clears `stuck` → `follow()` re-pins to bottom right after any manual scroll (element landed at y=−8958). Clear it with REAL wheel-up over the pane (`page.mouse.wheel(0,-800)`), then position.
  - Freeze live churn for deterministic UI tests by route-aborting `/oc/event`, `/oc/session/status`, `/session/*/message` — but only AFTER the fixture content rendered; freezing earlier aborts the tab's windowed message loads mid-flight ("no grep card" flake).
  - Element screenshots taller than the viewport go through CDP beyond-viewport capture: `content-visibility:auto` blanks the offscreen part of the `.msg` row and the sticky composer/status bar composite into the crop. Fix: tall viewport (1900px) so the whole element is on-screen; guard box-bottom < composer top.
  - Multiple mounted tab panes duplicate ids (`#composer-input` ×2 → strict-mode violation); scope locators to the active pane via `.tabpane[style*="flex"]`.

## Mobile soft-keyboard / visualViewport fix (webui, 2026-08)

- Chrome Android ≥108 defaults `interactive-widget=resizes-content`-less behavior to keyboard-overlays-layout; the shell (`height:100vh; overflow:hidden`) had zero overflow, so the composer was buried. Fix = three layers: (1) viewport meta now `…, viewport-fit=cover, interactive-widget=resizes-content` (index.html); (2) all four `100vh` sites (App `.app`/`.diffwrap`, Sidebar `.sidebar`, InfoPanel `.info`) use `height:100vh` + `@supports (height:100dvh){ height:var(--vvh,100dvh) }` — do NOT write `var(--vvh,100dvh)` outside @supports: engines without dvh drop the whole declaration (invalid var at computed-value time), losing the vh fallback; (3) `webui/src/lib/visualViewport.ts` mirrors visible height into `--vvh` on `visualViewport` resize+scroll (rAF-coalesced, pinch-zoom scale≠1 ignored, kb=innerHeight−vv.height−vv.offsetTop, ≤1px ⇒ removeProperty). Installed from App.svelte onMount, module-level idempotency flag for HMR.
- Verify script: `.webtest/verify-kbd.mjs` (stubs `window.visualViewport` via addInitScript defineProperty + EventTarget; asserts meta, dvh chain, 840px open / 1280px closed / pinch no-op / scroll-only wiring; shots in `.webtest/shots/kbd-*.png`).

## Agents / per-message "role" (engine API shape, verified v1.18.18 + dev docs, 2026-08)

- Proper term: **agent** ("primary agents" = build/plan). "mode" is legacy everywhere (config key deprecated, `.opencode/mode(s)/` dirs still load, message field `mode` is now just a mirror of `agent`). Careful: an agent config's own `mode` field means KIND (`primary|subagent|all`), not build/plan.
- `GET /oc/agent` (api.ts:124, wired but unused) returns the MERGED registry: built-ins + user config (`agent` key in opencode.json, `~/.config/opencode/{agent,agents}/**/*.md`, project `.opencode/…`) + plugin-config agents (oh-my-opencode-slim's orchestrator/oracle/… come back shape-identical; only differentiator is `native:false`). Also includes hidden/system (`compaction`/`title`/`summary`) and subagents → filter client-side like the TUI Tab-cycle: `mode !== 'subagent' && !hidden`. Listing order: configured/default agent first, then alphabetical.
- Per-message role selection = top-level `agent: string` in the body of `POST /session/{id}/prompt_async` / `/message` / `/command` (confirmed in live OpenAPI `/doc`; omitting = session default, usually `build`). Session-level default switch is v2-only: `POST /api/session/{id}/agent` `{agent}` (emits agent-switched events).
- Every stored message carries `data.agent` (user AND assistant). Webui label mystery root cause: `sse.ts normalizeMessages()` (~L128-153) rebuilds messages WITHOUT `agent`, so Transcript `roleLabel()`'s `'opencode'` fallback wins after every debounced refetch/reload; secondary gaps: `stores.ts upsertPart` bare base object and App.svelte's pure-history mapper. Mid-stream the label IS correct briefly via `setMeta` (the only writer that merges `agent`) — that's why it looks like it "changes after loading". Fix = copy `agent` in those three mappers (+ commands.ts export/copy headers).
- Built-in roster is version-dependent: 1.18.18 ships only build/plan (+ hidden system trio); dev adds general/explore subagents; docs mention unreleased `scout`. Plugins have NO classic register-agent hook; the v2 plugin API gets `ctx.agent.transform(draft)` — either way config/plugin agents converge into the same registry above, so the webui needs zero plugin-specific code.
- TUI prior art for labels: titlecase agent name (`## Assistant (Build · model · duration)` in transcript export) + tint via the agent's `color` config.
