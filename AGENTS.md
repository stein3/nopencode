## Known quirks

- Sessions created via the engine API don't appear in the TUI until refresh; cross-client live sync is not supported.
- `/workspace` inside the engine container must be the same worktree the TUI uses for session sharing.
- Stale "new session" tabs can 404 after engine restarts — delete them from the session list.
- **`mutateMeta` field-wipe bug (fixed 2026-08-30)**: `stores.ts mutateMeta()` built the update from `next[sid]` (undefined — the copy loop skips the target sid) instead of `all[sid]`, so every `setTag` silently WIPED the session's other meta fields (star, tag). Found via `e2e/embedded/session-filters.test.mjs` R3/R9 failures (star filter showed 0 after a tag add/remove cycle). Fix is one line: `next[sid] = { ...all[sid], ...patch }`. `toggleStar` was never affected (rebuilds from `all` explicitly).
- **Sidebar org model (2026-08-30)**: multi-tag system merged into folders — a session has at most one `tag` (localStorage `opencode.sessionMeta`, field `tag`); legacy `folder`/`tags[]` keys migrate on load (folder > tags[0]).

## Resource efficiency (2026-08 refactor)

- **chatserver.py is stateless (v0.2)**: every `/api` request runs its own read-only SQL against opencode.db — no full-DB RAM materialization (the old Store re-parsed all ~35k parts on every WAL mtime change; RSS grew with history). Measured 26 MB vs 156 MB steady-state. CPU re-measured under load: ~0.2%/client, <1% at 4 stress clients — a Go rewrite would buy nothing.
- **Status dots are solid circles** (no `pulse` keyframes anywhere). Kept intentionally: `.qwait` question-card text pulse, streaming-dots blink, Footer cylon — transient interaction cues, not ambient lights.
- **Pane dormancy (App.svelte)**: tabs outside active + `PANE_KEEP=5` most-recent render a placeholder (`dormant` prop → Transcript skips the msg each-block). Tab data stays in stores so remount is instant from memory; activation force-pins to bottom so no scroll restore needed. Verified: remount preserves message set, pin intact.
- **`.msg` rows use `content-visibility:auto` + `contain-intrinsic-size:auto 160px`** — offscreen rows skip style/layout/paint. Open latency (366-msg session): median 254 ms / longtasks ≤84 ms vs documented 500–700 ms / 90–156 ms before. Scroll math (maybeLoadOlder anchor, stick-to-bottom, jumpTo) unaffected.
- **Sidebar busy-poll is 10 s** (was 5 s) — halves per-client engine load; unread/busy worst-case staleness accepted.
- **Transcript endpoint windowing**: `GET /api/history/session/{id}?limit=N` returns newest-N ascending with parts fetched only for those messages (limit=50 → 207 KB/29 ms vs 3.45 MB/70 ms full on the 5.7k-part session). Client anchor jumps use capped `backfill(id, JUMP_CAP=600)` and fall back to uncapped when the anchor sits deeper; export/copy still backfill fully. Subquery gotcha: outer `ORDER BY time_created` needs the column projected inside the inner select.
- Search parity gotcha: sqlite's `lower()` is ASCII-only; `_connect()` registers a `pylower` UDF to keep unicode case-insensitivity identical to the old Python index.
- **Search results grouping (2026-08)**: `/api/search` hits carry `time` (ms epoch, from `part.time_created`) and SQL is `ORDER BY p.time_created DESC` — so the `SEARCH_CAP=300` cutoff keeps the NEWEST matches (was oldest-biased ASC). Grouping is client-side: Sidebar `groupHits()` buckets by session, sorts groups by latest-match desc, hits within group asc; header shows `relTime(latest)`. Flex gotcha: in a `space-between` header row both children shrink on overflow — `.grphead .meta` needs `flex: none` or "3m" ellipsizes to "3…". Verify: `e2e/embedded/search-groups.test.mjs` (local chatserver loop + headless; asserts group order vs API, hints, indent, click-through; screenshot in `e2e/.shots/search-groups.png`). Highlight (2026-08): `/api/search` snippets carry `\x00`/`\x01` sentinels around every case-insensitive match (window sliced from ORIGINAL text — casing preserved; manual scan, no regex); Sidebar `snipSegs()` parses them into `span.hl` (accent 28% tint, no `{@html}`) — raw consumers of `snippet` must strip the sentinels.
- Statics: hashed `/assets/*` served `Cache-Control: immutable`; `index.html` always revalidates via ETag/304. `.br`/`.gz` precompressed siblings are required for compression — generated by `webui/scripts/compress.mjs`, wired into `webui` `npm run build`. No siblings ⇒ silently uncompressed.
- **`webui/dist` is not in git** (ignored) — `Dockerfile.web` is multi-stage: stage 1 (node:23-slim) runs `npm ci && npm run build` and the final image (python:3.12-slim) copies only `dist` + `chatserver.py`. Never hand-edit dist; rebuild locally with `cd webui && npm run build` for dev, or `docker compose build opencode-web` which builds it fresh.
- **DiffPane/monaco are lazy-loaded** (`{#await import(...)}` in App.svelte) → main bundle 313 KB vs 2,989 KB. Do not statically import monaco or DiffPane anywhere else.
- Monaco glyph icons (fold chevrons beside unchanged regions, diff arrows, widget buttons) need the codicon font; `editor.api` never imports it → icons render blank. Fix lives in DiffPane.svelte (`import 'monaco-codicons.css'`) + a vite.config.ts alias, because monaco-editor@0.56's exports map forces subpaths to `*.js` and blocks deep css imports.
- **compose.yaml**: shared defaults via `x-limits` YAML anchor (`init: true`, mem/cpus caps, json-file log rotation 10m×3). Engine overrides to 3 GB (observed 1.2 GB growth); web 256 MB. Keep `init: true` — without it PID 1 doesn't reap children and zombies accumulate.
- **Two Dockerfiles, independent builds**: `Dockerfile` builds the **engine** image (`nopencode:latest` — opencode CLI + ttyd + inject.py/start.sh; no `build-essential`/pip/venv, assumes prebuilt npm binaries + stdlib-only python3; don't add compiling deps without restoring build tooling). `Dockerfile.web` builds the **web** image (`opencode-web:latest` — python:3.12-slim serving `webui/dist` + `chatserver.py`). Because the engine image no longer contains the webui, changing `webui/` or `chatserver.py` cannot bust the engine build cache — the two rebuild independently.
- Deploy changes: `sudo docker compose up -d --build` (image rebuild required for Dockerfile/Dockerfile.web/chatserver/webui/inject edits). To rebuild ONLY the webui without touching the engine: `sudo docker compose up -d --build --no-deps opencode-web`. inject.py additionally needs the cached `/app/index.html` removed (see ttyd-web-terminal skill).

## Streaming render cost (webui, 2026-08)

- Symptom: browser CPU pegged ~100% during long streaming "thinking" blocks (one tab suffices). Root cause: every `message.part.delta` re-parsed the ENTIRE accumulated part text — `html()`'s cache key is `${id}:${len}` so each delta missed cache — through marked+DOMPurify+`hljs.highlightAuto` (unlabeled fences = language detection across all bundled langs) → O(L²); plus an unguarded `afterUpdate` think-pin doing `scrollHeight` read + `scrollTop` write per update; deltas applied uncoalesced.
- Fix architecture (invariants — don't regress):
  - `markdown.ts md(src, live=false)`: module-level `liveParse` flag set around the synchronous parse. Fence caps: live unlabeled >4k chars / labeled >50k → escaped plaintext; final mode cap 100k; at/below cap → original hljs path. **Transcript's `renderCache` is written ONLY by the non-live path** — live renders may contain plaintext-fallback fences and must never satisfy a later final-quality lookup at the same length.
  - `Transcript.svelte streamThrottle`: live path stale-serves up to 120ms (`STREAM_THROTTLE_MS`) + exact-length fast path (deltas are append-only); entries pruned on non-live render. Non-live bypasses throttle → guaranteed full-quality final render at busy-flip (the color pop on big fences is intentional).
  - `sse.ts deltaBuf`: `message.part.delta` chunks coalesced per `${sid}|${mid}|${pid}|${field}` key with a single ~40ms flush timer; unmaterialized messages no-op at flush (unchanged semantics). A `message.part.updated` snapshot ALWAYS calls `dropBufferedDeltas(sid, pid)` before `upsertPart` — the engine applies deltas server-side before publishing the full-text snapshot, so any still-buffered chunk for that part would be re-appended on flush → transient duplicated suffix (fixed 2026-08-31; regression guard `e2e/embedded/stream-dup.test.mjs`, port 8168, delta+snapshot race must render the chunk exactly once).
  - Think-pin `afterUpdate`: rAF-coalesced (`thinkPinPending`), gated on `tab.busy && thinkStuck && !document.hidden`.

## Thinking message vanishes mid-stream (webui, 2026-08)

- Symptom: during a long "thinking"/reasoning turn, the thinking chat message disappears and its text is lost until the LLM finishes streaming. Root cause: `sse.ts` `message.updated` SSE events fire repeatedly mid-turn (live token tallies); each called `scheduleRefetch()` which set `dirty:true` then fetched `GET /session/{id}/message` and **replaced** `Tab.messages` wholesale. The engine snapshot for an in-progress reasoning part can hold less text than the deltas already accumulated locally (`bufferDelta`→`appendDelta`), so the live thinking got overwritten → it vanished, then reappeared at `session.idle` once the engine persisted everything.
- Fix (applied in `webui/src/lib/sse.ts`): gate the `scheduleRefetch(sid)` call in the `message.updated` handler on `!tabs.snapshot(sid)?.busy`. `message.part.delta` / `message.part.updated` (`upsertPart`) already keep the message current during the turn; final reconciliation still happens on `session.idle` via `Footer.svelte`'s busy→idle `refresh()`. Note `setMeta` only patches an ALREADY-EXISTING message (no-ops if not yet materialized) and `appendDelta` no-ops for unknown messages — so message creation still relies on the open-turn `openLive` refetch (App.svelte, ~150ms after send) plus the idle refetch. Don't delete those, or new messages won't materialize.
- **Follow-up if it recurs**: the catch-all `else { scheduleRefetch(sid) }` (end of the `onmessage` if/else-if chain in `sse.ts`) and the `session.updated` branch ALSO refetch mid-stream for certain unmatched events (`message.part.created`, `permission.asked`, etc.). If thinking still intermittently vanishes on turns that emit those mid-turn, gate those `scheduleRefetch` calls on `!busy` the same way as the `message.updated` fix.
- **Dist must be rebuilt**: `webui/dist` is what actually ships (git-ignored, built separately). A source fix does nothing until the bundle is rebuilt — `cd webui && npm run build` for a local dev loop, or `sudo docker compose up -d --build --no-deps opencode-web` (Dockerfile.web runs `npm ci && npm run build`). Restarting the container WITHOUT `--build` leaves the stale bundle serving the old code — the usual reason a source fix "doesn't take".

## Transcript scroll behavior (webui)

- Tab panes stay mounted under `display:none` (App.svelte), which silences their ResizeObserver (box stays 0×0) and makes the browser restore stale scrollTop on re-show — that synthetic scroll fires *after* RO delivery but *before* rAF, so pure position-based stick-to-bottom loses the pin on every tab return. Fix (Transcript.svelte): `active` prop force-snaps to bottom on activation, `onScroll` ignores events while `offsetParent` is null, and only real upward input (wheel-up / downward swipe / ArrowUp·PageUp·Home outside inputs) clears `stuck`.
- Streaming think-body pins itself in `afterUpdate()`: ResizeObserver can't work there — `max-height` caps the box size, so the observed box stops changing while content keeps growing.
- Svelte gotcha: attribute expressions like `open={p.id === someBoolean}` (string vs boolean) are silently always-false — no type error at build time (the old `lastThinkingOpen` bug that kept live thinking blocks collapsed).
- Svelte gotcha #2 (the frozen `{label()}` bug in ModelPicker): a function called in the template only re-runs when the function binding itself is dirtied — reactive vars/stores read *inside* the body are invisible to the compiler, so the collapsed model label never updated (stuck on "model…" or a raw fallback id). Fix pattern: `$: curLabel = fn($store, localVar)` and render `{curLabel}`.

## Session diff data (webui DiffPane)

- Engine `/session/{id}/diff` returns `[]` for real sessions (snapshot store has no commits) — derive per-session changes from the transcript DB instead.
- `part` table: `type`/`tool` live inside the `data` JSON — filter with `json_extract(data,'$.type')`, order by `time_created`.
- Completed `edit` parts (100% coverage) carry a real per-edit unified patch at `state.metadata.filediff.patch` (+ `metadata.diff`) — no need to synthesize old/new pairs.
- `write` parts have only new content (`input.content`; `metadata.exists`=was-overwrite). `apply_patch` has `input.patchText` in `*** Begin Patch` V4A format (Add/Update/Delete File sections), not unified.
- `type:'patch'` parts are just `{hash, files}` bookkeeping — ignore.
- Session changes endpoint (implemented): `GET /api/history/session/{id}/changes` → `{files:[{file, ops:[{k:'edit'|'write'|'patch'|'delete', t, patch?}]}]}`; edit→`filediff.patch`, write-create→`+` pseudo-patch, apply_patch→V4A split per file + converted to unified hunks (`_v4a_to_unified`, `force_add` for Add sections). Overwrites/deletes emit no patch (no before-image in transcript). JSON >1 KB is gzipped on the fly (~6x on patch-heavy sessions); ~30 ms warm.
- Client merges a file's ops via `mergePatches()` into ONE canonical multi-hunk patch — never concatenate raw patch texts (parsers stop at foreign headers).
- `applyPatchReverse()` uses tagged rows + nearest-hit continuity (seed from EOF) + longest-add-run fallback. Known-answer tests live in `/tmp/ocweb-test/`(ephemeral); regression guard shapes: real git multi-hunk patch → exact pre-image, pure-add hunk → rows deleted not blanked.
- Whole-file reconstruction drifts on huge chaotic op histories (later ops rewrite earlier additions) — inherent without snapshots; hunks view is unaffected (renders patches directly).
- DiffPane layout: monaco auto-flips side-by-side→inline below `renderSideBySideInlineBreakpoint` (900px default, opt-in flag set explicitly in DiffPane). Hunks models must swap pairs too: `parsePatch()` pads the opposite side with blank rows for side-by-side alignment — those blanks leak into inline view as stray empty lines, so inline uses `parsePatchInline()`. A ResizeObserver in DiffPane tracks the flip.

## Prompt send path (webui)

- `oc.prompt` (webui/src/lib/api.ts) uses engine `POST /session/{id}/prompt_async` — returns 204 in ms, body identical to sync `/message` (incl. `model:{providerID,modelID}`).
- **File attachments (2026-08)**: composer attachments ride the SAME call as extra parts — `{type:'file', mime, url:'data:<mime>;base64,<b64>', filename}`. Text/code files are auto-inlined by the engine as synthetic Read-tool text (model sees content); images pass through as image content. chatserver proxies bodies verbatim, so no server changes are needed. Rendering: Transcript renders stored `type:'file'` parts (images → thumbnail opening the lightbox; text/code → filename chip); the message filter + export/copy filters were widened so attachment-only messages survive. Verify: `e2e/embedded/uploads.test.mjs` (14 checks — attach-button tray, synthetic drag-drop, oversize guard, transcript render + lightbox; seeds its own fixture via prompt_async+abort and deletes it).
- **Engine file-part gotchas (verified v1.18.18)**: (1) `POST /session/{id}/message` with `noReply:true` REJECTS image file parts (`400 BadRequest`) — only `text/plain` rides noReply; images persist ONLY via `prompt_async`. (2) The engine **eagerly decodes image parts at prompt time** — a corrupt/undecodable image yields `ImageDecodeError` → `session.error` and the **entire message (including text) is dropped, nothing persists**. So fixtures must use a real decodable PNG (a 1×1 works). This is a silent-ish failure mode: `prompt_async` still returns 204.
- UI never depended on the POST resolving: busy flag + transcript come from SSE (`session.idle`/`session.error`). api.ts `req()` now tolerates empty bodies (204).
- No async variant exists for `POST /session/{id}/command` — long-running slash commands (e.g. /compact) hold the connection until completion.
- chatserver.py proxies `/oc/*` with `timeout=600`.

## Session error tiles (webui)

- Turn failures render as **full-red tiles** (faint `rgba(244,135,113,.09)` wash + red border, not just a side chip) in three places: (1) errored **tool cards** (`.toolcard.toolerr`, `state.status==='error'` — persisted parts, always rendered); (2) **inline tiles** on the assistant message the engine stamped `$.error` on (mid-turn provider failures, persisted in opencode.db, TUI-parity — `.errtile-inline` inside the message body); (3) **sidecar end tiles** (`tab.errors` → `.msg.errtile` after the last message) for instant fails that never created a message.
- Engine facts verified: mid-turn errors are stamped on the assistant message and served by `GET /message` (`$.error = {name, data:{message,statusCode,…}}`; 98 rows in DB) — but **instant fails (bad model) create no assistant message** and the `event` table stores no `session.error` at all. Readable text sits at `error.data.message`, NOT `error.message`; fallback chain `data.message → message → name → 'error'`.
- **Aborts**: engine fires `session.error` with `MessageAbortedError` for user aborts AND stamps it on the message. TUI-parity: excluded from tiles/persistence, rendered as muted italic "session aborted" (`.aborted`). Don't "fix" this into a red tile.
- Dedupe: a mid-turn failure can exist in BOTH sources (inline $.error + sidecar row from the witnessed SSE event) — Transcript filters sidecar tiles whose text matches an inline one (`inlineErrTexts`). Errored messages with **zero renderable parts** are kept by the msgs filter (common: provider died before any part streamed).
- Sidecar persistence: sse.ts POSTs to chatserver `GET/POST/DELETE /api/history/session/{id}/errors`, backed by `webui.db` next to opencode.db (table `serr`, `UNIQUE(sid,msg)` dedupes concurrent POSTs from several clients). compose.yaml dropped the `:ro` on opencode-web's share mount for this; opencode.db itself stays mode=ro+query_only. Tiles load once per tab open (`Tab.errorsFetched` guard — also keeps the onSent refetch from re-fetching rows it has). **Tiles are history, not a banner: nothing clears them automatically** — no clear-on-send (removed 2026-08 after a followup wiped the demo tile), no clear on idle; identical repeats dedupe via UNIQUE(sid,msg). DELETE endpoint remains for manual cleanup only. Coverage limit: only errors witnessed by an OPEN webui tab get recorded (TUI-only/background instant-fails leave no tile — mid-turn ones still show via $.error).
- Cheap real trigger: `POST /session/{id}/message` with `model:{providerID:'does-not-exist',modelID:'nope'}` → 500 + SSE `session.error`. Verify scripts: `e2e/embedded/errtile-persist.test.mjs` (live engine; reload persistence + survives-send; mocks only `prompt_async`→502) and `e2e/embedded/errtile-render.test.mjs` (fully mocked payloads; inline/abort/dedupe/tool-red/zero-part). Seed rows by writing `serr` in `~/.local/share/opencode/webui.db` directly (same file the deployed chatserver uses).

## Auto-retry of retryable turn failures (webui)

- `webui/src/lib/retries.ts`: when SSE `session.error` carries `isRetryable` (engine stamps it on transient `APIError`s, e.g. upstream 503 — shape `error.data.isRetryable`), the loop re-dispatches with backoff **1s → 2s → 3s → 5s → 15s → 30s → 60s → 2m → 5m**, then every 5m until the turn lands. Model comes from the picker (`selectedModel`) + per-session agent pick (`sessionAgent(sid)`), consistent with manual sends.
- **Nudge vs resend (2026-08)**: arming happens ONLY from a witnessed `session.error(isRetryable)` — and that event PROVES the engine accepted the original `prompt_async` (the turn ran, then the provider died mid-turn). Re-posting the original text would duplicate it in history on every attempt, so once armed each fire() sends the short **`STALL_NUDGE` = `"the session stalled, continue."`** instead. Entry point is `onRetryableError(sid)` (sse.ts session.error branch): it ARMS the per-session `loops` Map (`LoopState {orig, attempted, delivered}`, created with `delivered:true`) then calls `scheduleRetry`, which is timing/backoff only and never creates loop state. The verbatim-resend branch in `fire()` exists only for undelivered dispatches: if the synced transcript's newest user message equals `lp.attempted`, that attempt landed (→ flip `delivered`, nudge thereafter); otherwise resend `attempted || orig || newest`. A failed dispatch keeps `delivered` → a dead nudge re-nudges. `clearRetry` deletes the loops entry along with everything else.
- Loop lifecycle: attempt count persists across dispatches per session; a dispatch that itself dies (network) counts as a failure and re-schedules. Cleared by: clean `session.idle` (only when no error since the last dispatch — engines can emit idle AFTER session.error, so clearing on idle unconditionally would kill pending retries), manual send (Composer.submit `cancelRetry`), tab close, or missing loop state. Aborts (`MessageAbortedError`) are never retryable.
- UI: red countdown line under the error tiles (`.retryline` in Transcript) — "↻ retrying in 0:05 · attempt N · continue-nudge" + cancel button; the suffix comes from `nextPayloadKind(sid)` (`'nudge' | 'resend'`, read from the loops map, re-derived each tick from `$retryState` so it can't go stale); hidden while a dispatch is in flight (busy spinner covers that).
- Countdown is a 1s `setInterval` ticker → background-tab timer throttling can stretch delays; harmless (fires later, UI hidden anyway).
- Verified: `e2e/embedded/stall-retry.test.mjs` (replaces the deleted `verify-retry.mjs` + `fake-engine.py`; self-contained embedded fake engine on :8136 serving dist + stub /oc + scripted SSE via `/__ctl`/`/__state`, same conventions as verify-question.mjs — no separate engine process to start/kill). 25 checks: arm→nudge-not-original, clean-idle clears (attempt restarts at 1 on re-arm), re-arm nudges again, `failNextPrompt` (502) → reschedule → nudges AGAIN, retryline kind suffix, manual-send-cancels + no auto posts for ~3s, original text NEVER posted. Screenshot: `e2e/.shots/stall-retry.png`.

## Permission requests (engine API shape, verified v1.18.18)

- `GET /permission` items and the SSE `permission.asked` payload are `{id, sessionID, permission, patterns[], metadata{}, always[], tool?{messageID,callID}}` — there is NO `title`, `pattern`, `path`, or `type` field. The webui originally mapped those nonexistent fields, so pending permissions rendered as bare request-id prefixes.
- `permission` is the kind (`bash`, `edit`, `read`, `glob`, `grep`, `webfetch`, `doom_loop`, …). `metadata.input` holds the tool call input for bash (→ show `input.command`); glob/grep → `{pattern,path}`; webfetch → `{url}`; mcp reads → `{server}`. Edit asks carry the file path in `patterns[0]`.
- Human-readable detail builder lives in `webui/src/lib/permissions.ts` (`permDetail`); display in App.svelte header bar shows kind + detail with full text in `title`.
- Schema source of truth: engine `/doc` OpenAPI (`components.schemas.PermissionRequest`). Inspect a running engine's schema via `opencode serve --port <p>` + `curl /doc`; don't guess from TUI strings.

## Token/context tracking (webui)

- Engine reality: aborted turns, step-start/step-finish-only turns, and provider-silent responses permanently leave an **all-zero `tokens` object** on the newest assistant message (~28 sessions in opencode.db, 2026-08). An all-zero object is truthy, so "newest assistant message wins" logic read it as 0 context → sessions showed `—` tokens / `0% used` indefinitely.
- Fix pattern: `tokenTally()` (stores.ts) sums input+output+reasoning+cache and returns **undefined unless > 0**; `metricsFromMessages()` walks newest→oldest and OMITS the `tokens` key when nothing reported, so `patchMetrics` keeps the last good value. sse.ts guards its live `message.updated` patch with the same helper.
- Footer/InfoPanel now derive `usedTokens` from `$sessionMetrics[tab.id]` (SSE-live DURING a turn) with their busy-keyed fetch only seeding values — previously they fetched once at busy-flip = turn start, when the newest message is always a zero-tally in-flight one, and never updated until idle.
- chatserver `load_sessions()` computes a per-session context estimate via correlated subquery over `message_session_time_created_id_idx` DESC with a `TOKEN_SUM_SQL > 0` predicate — stops at first hit, ~1–2 ms for ~150 sessions. The naive window-function full scan costs ~105 ms (json_extract parses every blob) — don't use it.
- Engine session-level `tokens` on `GET /session/{id}` are CUMULATIVE all-turn totals (cache.read in the millions), NOT context size — never use them for "% used".
- Verified headless: `e2e/embedded/tokens.test.mjs` (sidebar 140/156 rows show tk badges; InfoPanel 93K / 9% on ses…D0hlIGZU which previously rendered `—` / 0%).

## Session status lights (webui sidebar)

- Each sidebar session row has a 7px dot with three states (source order in Sidebar.svelte matters — later rules win): `.perm` red solid (pending permission), `.busy` yellow pulsing, `.unread` accent green slow-pulse (finished while unviewed). Idle = transparent.
- Busy comes from a 5s poll of engine `/oc/session/status` in Sidebar.svelte (`busyMap`); permission from the shared `permissions` store.
- Done/unread lives in `sessionUnread` store (stores.ts). Two producers: sse.ts marks on `session.idle`/`session.error` when `tabs.getActive() !== sid` (open tabs only — SSE drops non-open sessions); Sidebar's busy-poll diffs consecutive polls to catch busy→idle for sessions with no open tab. Consumer: App.svelte `$: if ($active) clearSessionUnread($active)` clears on any tab activation (clicks, hotkeys, new chats).
- Unread state is in-memory only — lost on reload by design (no localStorage persistence).
- Subagent sessions (@explore/@general/…): engine marks them with `session.parentID` (+ `agent` name); sqlite columns are `session.parent_id`/`session.agent` (snake_case). chatserver `load_sessions()` exposes them as `parent`/`agent`; Sidebar NESTS them under their parent (chevron + count chip, indent + tree guide, per-parent collapse persisted as an EXPANDED-id set in `opencode.subExpanded` localStorage (`subExpanded` store in stores.ts — inverted so empty = all collapsed = the default; new parents collapse automatically), depth cap 2). Collapsed parents show a SOLID aggregated dot (red perm / yellow busy / dim accent unread) when a descendant needs attention — no pulse animations anywhere (resource-efficiency decision). The "hide subagents" checkbox (`hideSubagents` pref, ON by default) removes sub ROWS but since 2026-08 parents still show the aggregated light in hide mode: `displayRows`' hidden branch runs `flattenTree` over `visible` and flags root rows `subsHidden` — light renders on `(d.subsHidden || !d.expanded)`, chevron gated off by `!d.subsHidden` while the count chip renders regardless; search hits are NOT filtered/nested. Row layout (2026-08 redesign, REVISED later that month): line 1 = `.chev`/empty `.chevslot` (fixed 16px column reserved on EVERY row so lights/titles align whether or not a row has kids) → `.dot` → `.ttext` → `.aggdot` (inline, collapsed/hidden parents only) → `.kidcount`. ## Windowed message loading (webui)

- Engine pagination reality (v1.18.18): `GET /session/{id}/message?limit=N` returns the NEWEST N ascending ✓; the `before` param 400s server-side in every form; the v2 `/api/session/...` tree returns empty data for legacy sessions. - Open path: `openLive` fetches RECENT_PAGE=80 → `Tab.partial` set from completeness; refetch paths (SSE debounce, Footer, InfoPanel, /undo) are limited too and pass `complete = len < limit` so `metricsFromMessages` skips overriding the sidebar's true sqlite message_count on truncated payloads.
- Scroll-up paging: Transcript `maybeLoadOlder` triggers <900px from top; anchor math keeps `scrollHeight - scrollTop` constant across prepends; auto-chaining stops at AUTO_PAGE_CAP≈400 loaded — deeper history via explicit "↑ load earlier messages" button (unbounded chaining crashed even prod headless at ~1.5k msgs/~40k nodes; desktop browsers survive but it's wasteful).
- `backfill()` (full fetch) is reserved for transcript export/copy and search-anchor jumps; App sets `Tab.jumpTo`, and TRANSCRIPT owns the scroll: reactive waits for the node, clears `stuck`, parks, clears flag — and `follow()` no-ops while `jumpTo` is pending (its force path would otherwise yank back to bottom during multi-tick row insertion; a bare rAF+scrollIntoView in App loses that race).
- CRITICAL invariant discovered: any `tabs.patch` swaps the Tab object → every consumer reactive re-fires. An async fetch whose completion patches tabs self-amplifies into a request storm (Footer once hit ~20 req/s when engine-side streaming churned tabs). Guards now: Footer keys refreshes on `${id}:${busy}` (InfoPanel already did), and `applyMessages` skips the swap entirely when fetched id-set + partial state are unchanged.

## Hotkeys: Home/End scroll, Alt+W, Focus mode (webui, 2026-08)

- **Browser-reserved chords reality**: Ctrl+W / Ctrl+Shift+W are NOT capturable by web pages in normal tabs on any engine (Firefox bug 1291706 WONTFIX; Chromium handles accelerators pre-renderer; Safari reserves them). The keydown fires but `preventDefault()` is ignored — hotkeys.ts `mod+w` branch runs AND the browser closes the tab. Only capture path = JS-initiated fullscreen + keyboard lock.
- **Focus mode** (`webui/src/lib/kbdlock.ts`, ⌨ topbar toggle): `requestFullscreen({keyboardLock:'browser'})` (Firefox ≥151 / Safari 26.4+) with plain-fullscreen fallback, then best-effort `navigator.keyboard.lock(['KeyW'])` (Chromium-only; captures W with ANY modifiers incl. Ctrl+Shift+W; Chrome 130+ prompts once). Lock auto-releases on fullscreen exit/tab switch — UI tracks `fullscreenchange`, not intent. Esc-hold ~2s is the uncapturable escape hatch. Ctrl+Shift+W intentionally mirrors Ctrl+W (same branch matches both — no Shift exclusion).
- **Alt+W** is the cross-browser close-tab fallback (hotkeys.ts). Alt-chord matching MUST use `e.code === 'KeyW'`, not `e.key` — macOS Option+W composes 'œ'.
- **Home/End transcript jump** lives in Transcript.svelte `onKey` (NOT hotkeys.ts — scroller ref + stick machinery are pane-local). Order matters: editable-target guard FIRST (inputs keep native caret keys), then `!active || dormant` guard (up to PANE_KEEP recent panes stay mounted under display:none and their window listeners fire). Home = unstick + scrollTop=0; End = stick + `follow(true)`; both cancel pending `tab.jumpTo`. Guard patch calls with `if (tab.jumpTo)` — tabs.patch swaps the Tab object unconditionally (request-storm family).
- **Headless test caveat**: Chromium reads `scrollTop` as 0 for any `display:none` subtree (no CSS boxes) — hidden-pane scroll position is UNOBSERVABLE directly; prove pane-guard behavior indirectly (active pane jumps while sibling mounted + sibling re-pins cleanly on reactivation). Harness: `e2e/embedded/hotkeys.test.mjs` (12 checks; seeds probe sessions via noReply POSTs; cleans up engine sessions + chatserver PID).

## Engine retry-loop state & the webui blind spot (root-caused 2026-08-30)

- Provider limit errors (e.g. opencode-go "Free usage exceeded, subscribe to Go") do NOT
  surface as errors: the engine's internal retry policy (`session/retry.ts` + `Effect.retry`
  in `processor.ts`, v1.18.18 source) keeps the turn RUNNING and sets session status
  `{type:"retry", attempt, message, action:{reason,provider,title,label,link}, next}`
  (next = epoch ms of next attempt; delay honors retry-after headers → hours; max 5 attempts,
  THEN a final error lands on the message). While retrying: NO `session.error`, NO
  `session.idle`; the in-flight assistant message has empty parts and NO `error` field.
- Retry state is exposed ONLY by: (a) ephemeral `session.status` SSE event fired at each
  attempt (NOT replayed — a tab opened after the stall sees nothing), and (b) poll-able
  `GET /session/status` snapshot (in-memory map). The TUI renders it from its
  `session_status` sync data. Verified live: stalled sessions appear ONLY in
  `GET /session/status` (`ses_fab9c0e24ffe…`, `ses_fab9e68fcffe…` on 2026-08-30).
- Webui gaps that made this invisible: `sse.ts` has NO `session.status` branch; its
  `session.next.retried` handler (L308) is dead code for this engine (wrong event name AND
  wrong payload shape — real data is at `p.status.*`, not `p.attempt`/`p.error`). The only
  `/session/status` poller is Sidebar's busy-dot loop (payload discarded). `retries.ts`
  never arms (needs `session.error` w/ isRetryable). Result: endless spinner (webui-sent)
  or total silence (TUI-sent session viewed in webui).
- Recovery API facts (v1.18.18 source + /doc): `POST /session/{id}/abort` interrupts the
  retry fiber → assistant msg finalized with AbortError, keeps your user message, session idles.
  `POST /session/{id}/revert` `{messageID, partID?}` enforces `assertNotBusy` → **409
  `{name:"SessionBusyError", data:{sessionID, message:"Session is busy: …"}}` while the retry
  loop is live** (user-observed "revert failed 409" in webui). Same guard on unrevert/shell/
  DELETE message; `/abort` and `/fork` have NO busy guard. Per-request model override rides
  `prompt_async` body `model:{providerID,modelID}` (already sent by Composer.submit).
- TUI undo parity pattern (packages/tui session/index.tsx ~L614): if `session_status[sid].type
  !== 'idle'` → `await abort()` then `revert(lastUserMsg)` + refill prompt input from the
  reverted message's non-synthetic text parts + file parts. No poll-loop needed: the abort HTTP
  response returns only after the server-side fiber-interrupt finalizers run, so an awaited
  abort guarantees the following revert passes `assertNotBusy`.
- Manual unblock without any code: `curl -X POST http://127.0.0.1:4096/session/<sid>/abort`,
  then revert/edit-resend with a different model.
